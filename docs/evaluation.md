# Race Pit Strategy Evaluation

No replay has been evaluated in this workspace, so no performance or strategy
metrics are claimed yet. With Docker Compose available, run the evaluator first
from the repository root:

```bash
make evaluate EVAL_SPEED=1
```

The command starts a one-shot replay server which waits for Spark to connect.
In a second terminal, start the consumer:

```bash
make submit
```

Repeat with `EVAL_SPEED=5` and `EVAL_SPEED=20`. Restart the Spark streaming
consumer for each replay speed. The evaluator starts a one-shot FastF1 streamer,
waits for replay-tagged Gold rows to settle in HBase, and updates this report,
the threshold-sweep plot, and the throughput/latency plots. FastF1 and the
Python dependencies in `requirements.txt` must be installed on the host running
the evaluator; Docker Compose and the running Spark/HBase services are also
required. Override the race with `python evaluate.py --year 2023 --gp Monaco`.

Evaluation uses a one-to-one match between a trigger episode and the next
actual pit-in lap on that driver, only if the stop is within five laps (adjust
with `--max-lead-laps`). Consecutive triggered laps count as one trigger.
Precision is matched trigger episodes divided by all trigger episodes; recall
is matched actual stops divided by all actual stops. Mean lead is averaged over
matched triggers. The regression rule is `decay > margin OR cliff_detected`;
the classifier rule is `pit_probability >= 0.5`; the combined rule is either.
The threshold sweep tests margins from 0.10 through 0.40 seconds in 0.05-second
increments.

Throughput is the FastF1 replay input record count divided by its actual send
loop duration. End-to-end latency is measured from the source telemetry
`ReplaySentAt` carried by each scored Gold record to its HBase `processed_at`
write timestamp; p50 and p95 include only Gold samples with both timestamps.
